The input CSV schema is exactly:

Severity,Score,Id,Source,Package,PackageVersion,URL,FixedVersion,Description

Implementation requirements:

1. Locate the CSV only through:
   bundle.member("ez-scan.csv")

   Do not search directories, reopen the original ZIP, or accept an arbitrary
   untrusted CSV path.

2. Confirm that the bundle member exists and that its StoredArtifact still
   matches RunDirectory.describe_artifact(...). Reject hash or size mismatches.

3. Use only Python's standard csv module. Do not use pandas.

4. Open the CSV as UTF-8 with optional UTF-8 BOM support and correct newline
   handling.

5. Require all nine expected columns. Reject missing or duplicate normalized
   column names. Extra columns may be ignored, but record a warning listing
   them.

6. Treat an empty CSV with only headers as a valid scan containing zero
   findings.

7. Row normalization:
   - Strip surrounding whitespace from every value.
   - Id, Package, and PackageVersion are required.
   - Normalize Severity case-insensitively.
   - Recognize Critical, High, Medium, and Low.
   - Unrecognized severity becomes FindingSeverity.UNKNOWN and adds a warning.
   - Empty, N/A, NA, None, null, and not available scores become None.
   - A nonempty malformed score raises EzScanIngestError with the row number.
   - Scores must be between 0 and 10.
   - Empty, N/A, NA, None, null, and not available FixedVersion values become
     None.
   - Empty Source becomes "unknown".
   - Empty URL and Description become None.

8. Package-prefix normalization:
   - python: or pypi: -> PackageEcosystem.PYPI
   - npm: or node: -> PackageEcosystem.NPM
   - maven: or java: -> PackageEcosystem.MAVEN
   - rpm: or rhel: -> PackageEcosystem.RPM
   - deb: or debian: -> PackageEcosystem.DEB
   - apk: or alpine: -> PackageEcosystem.APK
   - Remove only the recognized prefix from the normalized package name.
   - Preserve the complete original value in raw_package.
   - A package without a recognized prefix remains
     PackageEcosystem.UNKNOWN with EcosystemSource.UNKNOWN.
   - Do not guess that unprefixed mammoth, litellm, or starlette are Python.
     SBOM enrichment will handle that later.

9. Evidence:
   - source_artifact is the member's stored relative path.
   - source_sha256 is the member's stored SHA-256.
   - source_row is the physical CSV row number beginning at 2.
   - scanner_source is the normalized Source value.

10. Deterministic deduplication:
   Use this normalized key:
   - case-folded vulnerability ID
   - ecosystem value
   - case-folded package name
   - installed version
   - fixed version or an empty string

   For rows with the same key:
   - Merge scanner_sources and evidence.
   - Keep them unique and deterministically sorted.
   - Keep the highest recognized severity.
   - Keep the largest non-None score.
   - Preserve the first nonempty URL and description in CSV order.
   - Increment duplicate_rows_merged.

   Rows with different fixed versions must remain separate findings.

11. Create a stable finding_id from a SHA-256 hash of a canonical JSON encoding
    of the deduplication key. Use the format:
    ezscan-<first 24 lowercase hex characters>

12. Sort final findings deterministically by:
    - descending severity
    - vulnerability ID
    - ecosystem
    - package
    - installed version
    - fixed version

13. Produce EzScanIngestionSummary containing:
    - total CSV data rows
    - unique findings
    - merged duplicate count
    - severity counts
    - scanner-source counts from original rows
    - unknown ecosystem count across unique findings
    - unresolved fixed-version count across unique findings
    - deterministic warnings

14. This module must be deterministic and read-only. It must not:
    - write artifacts
    - change the manifest
    - call EZ-Scan
    - use the network
    - parse acs_result.json or nv_result.json
    - clone or modify Git repositories
    - invoke an LLM

Artifact persistence will be added separately in artifacts.py.
